## Critical findings (P0)

- [ ] **DL-AUD-001 — Downloads screen does not refresh itself. [V,S]** At ~00:25–03:10, ~03:45–05:15 and ~08:40–11:30, progress/statuses visibly stay stale until the owner switches to Home/Search or re-enters Downloads; a re-entry shows a fresh item or updated state. `UnifiedDownloadsUi.render` defines a 3-second poll but schedules its first tick ONLY inside an `OnAttachStateChangeListener` registered **after** `parent.addView(surface)`. When inserted into the already attached Activity body, the attach event may have fired before listener installation, so `poll()` never starts. It also abandons refresh when `surface.parent!==parent`, when detached, or when read is still in flight. **Required:** start an explicit initial visible poll and lifecycle-aware state observation regardless of attach timing; emit an in-place update on DB/engine events and at bounded ~1–3s while foreground; teardown on detach; verify in a continuous 60s screen recording without tab switches, and after stop/resume/process recreation. Never spawn duplicate poll loops.
- [ ] **DL-AUD-002 — Provider content/index is not live without manual or navigation refresh. [V,S]** Repeated Porn/Hentai catalogs and source preview cards require re-entry/`REFRESH PREVIEWS` before changed indexed content appears (~00:15–00:30, ~03:15–03:25, ~06:30–08:10). `AsterionAdultHub.render` has callback-coalesced repaint but no listener to independent SourceIndex/VideoDb changes; first render is a snapshot. **Required:** observe/notify precise per-provider index commits and preview ingestion, automatically update only the affected source card, preserve scroll and media ownership, do not perform network scans merely to repaint.
- [ ] **DL-AUD-003 — Saved total 71 is not authoritative; Pixiv count is artificially capped at 70. [V,S]** The overview repeatedly shows **71 saved = Video 1 + Pixiv 70**, even while Pixiv artists report hundreds of expected works and ongoing backfill (~00:05 to ~14:25). `UnifiedDownloadsUi.collect` queries MediaStore and stops at `found<70` recent image rows. `exactModuleTotals` has Video/X/Chapter/Novel/remote tables but no actual Pixiv/Gallery full archive count. This is **not** proof there are exactly 70 Pixiv files. **Required:** indexed exact per-module totals from the actual Pixiv and Gallery stores + verified files, not a truncated 70-row display list; independent active/queued/failed count by module; no double counting cloud/local receipts.
- [ ] **DL-AUD-004 — "Downloading" and "Live transfers" conflate resolving with bytes transferring. [V,S]** For long intervals (~00:25–00:40; ~03:25–04:05; ~08:35–09:35; ~10:35–11:40) a video is shown as **1 downloading/active** while its live card reads `Inspecting / preparing original` or `Connecting to original`, with zero demonstrable byte change. `UnifiedDownloadsUi` maps VideoDb state `running` immediately to State.ACTIVE even while resolving publisher/player. **Required:** separate `Resolving` / `Connecting` / `Receiving bytes` / `Verifying` / `Retry wait`; only label a file "Downloading" if its transfer stage and current bytes support that status. Do not inflate concurrent download counts with URL-resolution tasks.
- [ ] **DL-AUD-005 — Video percentage and byte progress disagree. [V,S]** A video is reported ~1–2% while its journal says hundreds of MiB received, e.g. **~840.6 MiB** around 02:35–03:05. Current card takes `VideoDb.progress` (extractor/engine stage percentage) and `VideoTransferJournal.verifiedBytes` (bytes) without a verified common total. **Required:** compute file percentage only from actual received/expected byte total, or display "size unknown" with received bytes and measured speed; stage percentage must be separately labelled. ETA only when total and speed are reliable. No artificial progress bar.
- [ ] **DL-AUD-006 — Large received video disappears without visible full-original receipt. [V,I]** Around ~02:35–03:05 the same live row shows ~840.6 MiB received, then no live transfer, while total saved stays 71. It may have been cancelled/failed/preserved in partial storage; the video alone cannot distinguish. **Required:** correlate job ID, lease, output path, actual file size, playable duration, full-file hash and terminal transition; preserve partial file on transient failure and report the exact result, never silently promote or discard it.
- [ ] **DL-AUD-007 — Failing provider attempts accumulate; no successful newly verified full original. [V]** "Needs attention" grows from **0 → 1 (~05:05) → 3 (~06:40) → 4 (~09:55) → 5 (~10:20) → 6 (~12:20) → 7 (~12:35)** while saved stays 71. Workers still advertise new jobs as "Selected original queued" without proving exact original availability. **Required:** distinguish request accepted / original resolved / bytes flowing / verified media; classify terminal versus transient errors; avoid unbounded job churn and blind retries of unsatisfiable sources; provide per-job failure recovery and route to source authentication only when needed.
- [ ] **DL-AUD-008 — Failure details clipped / no usable recovery screen. [V,S]** Open Video module displays only `Latest issue` followed by the first ~110 characters, clipped to partial phrases (e.g. "configure an a"; "choose the exac"). `show` uses `take(110)` and renders only the first failed/held item, not a navigable list of all 3–7 failures. **Required:** one clear "Needs attention · N" entry opening filtered errors with source, status, exact selected item, readable full sanitized cause, Retry/Sign-in/Verify host/Discard where relevant. No random red error text below unrelated module actions.
- [ ] **DL-AUD-009 — Misleading global/module commands and no contextual failure actions. [V,S]** Global PAUSE in header, a second PAUSE under an expanded Video module, an ellipsis for the live row and CANCEL when **0 active, 0 queued, 3 failed** (~06:40). `show` derives bulk cancel from any non-DONE row, including terminal errors. **Required:** global pause is clearly named and scoped; inside a module show Pause/Resume only for transferable jobs, Cancel only for queued/active, Clear failed vs Retry failed vs Remove history separately, retain saved originals. Never use "Cancel" to silently dismiss a failure. Collapsed rows should not require repeated CLOSE/MANAGE to see true state.
- [ ] **DL-AUD-010 — Explicitly queued items can sit without an active worker or position/retry reason. [V,S]** ~04:05–04:15, ~05:05 and ~12:35 show 0 live with 1 queued while no reason or ETA is provided. `recoverIdleQueues` runs from screen read, throttled three minutes, and bails when any other row is active; this is not a reliable real scheduler. **Required:** durable worker wake independent of opening Downloads; per-queue reason (waiting slot, cooldown deadline, permission, source/host, network, paused), persistent automatic transient-only retry.
- [ ] **DL-AUD-011 — Video source catalog "0 source errors" masks transfer failures. [V,S]** Porn overview initially reports indexed media cards and **0 source errors**, yet the download queue later contains 3–7 failures. `AsterionAdultHub.renderContents` counts errors only among sources with no visual cards; sources with previews can have broken originals. **Required:** separate *catalog/thumbnail health* from *selected-original transfer health* and *backfill state*, with meaningful per-provider badges; a poster URL is not a verified original.

## Required release gates before declaring acceptance

1. **Live state**: while continuously viewing Downloads, real recorded byte increments and transitions appear within a bounded ≤3s cycle (or faster event push) **without tab changes**. Publisher preview/backfill changes update their own cards automatically. No duplicated polling threads or full Activity rebuild storms.
2. **Numerical truth**: exact Pixiv/gallery/video/novel/comic/torrent/cloud original counts from durable sources; missing/partial/verified distinct; no 70 or 100-row visual cap masquerading as total, no double counting.
3. **State truth**: Resolving, Transferring, Retry at time, Waiting for slot, Paused, Needs authentication, Failed, Verifying, Saved with verified original. Only actual byte transfers in live file section; exclude images' individual live rows as owner specified.
4. **Action truth**: contextual module and item Pause/Resume/Cancel/Retry/Clear fail, working even after process death; do not cancel completed originals, and never label terminal errors as active. No repeated global commands or out-of-place text.
5. **Provider gate**: exact publisher-selected original for every seven owner-targeted providers (and formerly working providers regression) on Android: bytes, valid playable stream duration/audio/video, hash, selected identity; no HTML previews/CAPTCHA/foreign media counted. Where legitimately blocked, show actionable distinct outcome, no invented download.
6. **Torrent gate**: legitimate index->metadata->file selection->peer bytes->full file->pause/resume/verified original or explicit no-peer/network cause. No unrelated result pollution or unbounded metadata toast storms.
7. **Pixiv/cosplay/3D/X gate**: real account followed IDs and album/post selection, original card metadata, known archive counts and complete correct originals. Persisted retry and stable UI without default one-tap arbitrary imports.
8. **Crash & privacy gate**: Asterion Control log/incident receipts for closed-app crashes, background/foreground service recovery, no credentials or signed URL in displayed errors/logs, no data wipes or signature changes.
