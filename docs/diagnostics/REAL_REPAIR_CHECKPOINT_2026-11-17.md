## Implemented source-level corrections
1. **Hentaibros selected-original fallback:** `SiteSpecificOriginalSources.selectedStatic` now returns the selected `wpfp_*` WordPress source without appending unrelated HTML5 videos from the same wrapper, even when they are fully playable. Committed `84568ac`, with scenario regression `a0a07ee`.
2. **Transfer interrupted without an HTTP ETag:** `NativeMediaDownloader` now binds every in-progress `.part` to a SHA-256 fingerprint of the exact original URL and, when ETag is missing, confirms a 64-byte overlapping HTTP Range before appending. If the bytes differ, it discards the mismatched partial and refuses to publish mixed content. Commit `c9cd5d3`; tests `c233ddc`.
3. **Staged complete file reuse across selected videos:** a valid length/SHA receipt no longer authorizes returning a different candidate's staged original. The final receipt must also match the selected-source fingerprint; the hashed binding survives completion. Commit `2073662`, test `3a3cadc`, adjusted fixture `f1a55e5`.
4. **Hentaibros dynamic WebView source:** `BrowserPageFetch` retains an unambiguous selected rendered `.video-player [data-item]` configuration in the compact article snapshot. This lets the existing first-party selected-player resolver inspect the precise WordPress source after JS initialization, instead of treating generic videos as originals. Commit `32934c1`. Dynamic presence is **not** proof of a full download.
5. **No unrelated generic fallback after strict selected provider resolver:** `PublisherOriginalExtractors` excludes related/sidebar/advert elements even if runtime looks full-length, and uses the exact selected site resolver for the 11 sites with dedicated player contracts rather than appending generic media from recommendations. Commit `890b02e`, test `555001a`.
